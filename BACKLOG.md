# Future Enhancements

- Require login again when app is fully closed and reopened (currently stays logged in — intentional for now, to make testing easier)
- Map: tapping a cluster bubble sometimes only partially expands it (e.g. a "16" cluster reveals a couple of sub-clusters instead of jumping straight to individual pins), needing a second tap to fully expand. Confirmed via a standalone test this is normal, expected behavior for hierarchical clustering when many sightings share almost the exact same spot (the library only guarantees the *next* level of the cluster tree per zoom step, not a full expansion to leaves in one jump) — not a bug, just worth knowing if it comes up in feedback.
- Map: sightings within a few meters of each other may never fully separate into individual pins, even at max zoom. Confirmed via on-device breadcrumb evidence that MapKit's animateToRegion reliably reaches zoom ~19-20 but not 21+ on this device — cluster expansion is capped at 20 to match, so a same-spot cluster tighter than that stays as a badge permanently rather than leaving cluster taps looking unresponsive. Not expected to come up often in real usage (it took repeated same-spot test saves to reproduce), but worth knowing if it comes up in feedback.
- Map: a pin's Callout can briefly pop up and then disappear on its own, specifically when several pins are only a few meters apart on screen (the same tightly-packed same-spot test cluster as above). Confirmed via breadcrumb evidence that the JS-level selection state (Marker onPress/onDeselect) behaves correctly in every case — every deselect lines up with a legitimate subsequent tap on another pin or cluster — so this looks like a native MapKit rendering quirk when callouts for near-overlapping pins compete for space, not a state bug. Confirmed NOT to happen on normal, well-separated sightings. Low real-world impact (requires several near-duplicate GPS saves), not investigated further.
