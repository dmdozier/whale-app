# Future Enhancements

- Require login again when app is fully closed and reopened (currently stays logged in — intentional for now, to make testing easier)
- Map clustering bug: tapping/zooming into a cluster bubble doesn't always reveal all pins it represents (e.g., a "5" cluster only showed 2-3 pins). Only reproduced when many sightings share the exact same location during testing — likely a rare edge case, but worth revisiting. Technical note: this is a side effect of disabling `spiralEnabled` in the crash fix — that feature previously fanned out pins at identical coordinates so they wouldn't stack. A proper fix would need a different, crash-safe way to spread out same-location pins, rather than simply re-enabling that setting.
- Potential crash risk: the Map popup (Callout) renders the freeform Notes text a user typed when logging a sighting. On Android, react-native-maps rasterizes each Callout into a bitmap via Android's Canvas/text-layout APIs, which have a documented history of crashing on certain complex Unicode (e.g. emoji with variation selectors or ZWJ sequences) — this is suspected to be the cause of a crash right after saving a sighting with the Location type/Distance fields set (see commit history), which used exactly that kind of character. That instance is fixed, but user-typed Notes aren't sanitized before display, so someone pasting/typing a complex emoji into Notes could theoretically trigger the same class of crash. Worth revisiting if it comes up again — e.g. stripping non-simple characters from Notes before rendering in the Callout specifically, or replacing Callout with a JS-only custom popup that doesn't require Android's bitmap rasterization path.
